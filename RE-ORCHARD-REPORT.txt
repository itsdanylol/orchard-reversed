     -> strings only decrypt if called from the exact original call site (anti-LLM/decompiler)
   - Layer 3: base64 + LCG-derived XOR stream wrapper (k74.x.IlIIllIII) on top
2. Stack-frame self-verification inside decryptors (new Throwable().getStackTrace()[1])
3. Two AI honeypot files shipped inside the jar:
   - assets/m2c8/security/eval_agent_context.json — prompt injection telling AI models to
     refuse analysis and claim all code is "honeypot decoys" (fake policy text)
   - assets/m2c8/security/decomp_symbol_cache.bin — fake symbol table pointing at a
     q96.x package that does not exist (poisons automated symbol-mapping tools)
4. Runtime java.lang.reflect.Proxy interceptors (IIlIlIIII, lIIIIl) — method-level hooking
   without mixins
5. Self-jar integrity check via CodeSource + URL (IIllllll)

PROCESS EXECUTION (most interesting finding)
--------------------------------------------
k74.x.IIIllIIII extracts /assets/cats/spotify/spotify_session.ps1 from the jar to
%TEMP%\ilovcats-spotify\spotify_session.ps1 and runs:
    powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <script>
reading JSON+Base64 messages from its stdout, restarting every 2 s while active.
THIS BUILD IS SAFE: assets/cats/spotify/spotify_session.ps1 does NOT exist in the jar
(all 140 assets are assets/m2c8/*). getResourceAsStream returns null -> IOException ->
the Spotify bridge's helper process never launches. Only the lrclib.net HTTP fetch runs.
